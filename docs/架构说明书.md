## 1. 项目背景

### 1.1 问题

现代 IDE 中的 AI 辅助（补全、对话、任务理解）高度依赖**动态上下文**：用户正在看什么、改了什么、近期意图是什么、代码库中哪些符号与当前位置相关。若上下文仅做「打开文件 + 光标前后若干行」，会丢失：

- 近期编辑/选区/终端操作轨迹；
- 跨文件的引用、调用、类型定义等**硬关系**；
- 用户反复在两处跳转形成的**软关系**；
- 关键词检索得到的外围相关片段；
- 由行为序列归纳出的**当前任务**。

VirtualME 项目中的 **Foreshadow** 子系统正是为上述「七项动态上下文」设计的中间层。完整 VirtualME 还包含光标预测引擎（CursorPredictor）、采纳界面、蒸馏与用户画像等模块；这些与「上下文构建」可解耦。

### 1.2 本仓库定位

**Foreshadow 独立插件**从 VirtualME 中剥离并独立交付：

- **数据底座**：行为日志、工件（Artifact）抽取、RepoMap（硬/软关系、搜索、缓存）、任务识别编排；
- **上下文层**：七项上下文的状态维护、去重与结构化导出。

目标是形成**可迁移架构**：业务逻辑（L2/L3）不依赖 VS Code API，平台差异收敛在 Host Adapter（L1），便于后续替换 Host 或在无 UI 环境用 fake ports 复用同一套结构化与导出逻辑。

### 1.3 与 VirtualME 的关系

| 维度 | VirtualME | 本插件 Foreshadow |
|------|-----------|-------------------|
| 运行时依赖 | 完整插件生态 | **无** VirtualME 依赖 |
| 数据目录 | 常为 `.virtualme` | 默认 `.foreshadow`（可配置） |
| 上下文层 | 有 | 有（对齐七项 + 导出） |
| 光标预测 / Tab 采纳 / 蒸馏 | 有 | **非目标，不实现** |
| 用户画像 / 知识点 | 有 | **非目标** |
| 分层 | 历史实现与 vscode 耦合较深 | **严格四层 + Port** |

对照源（只读）：`virtualme2` 中 `core/cursor-pred/foreshadow.ts`、`vm-repo-map`、`log-beh-extract`、`task-beh-recognize` 等。本仓以 SPEC v0.2 为实现基线，而非目录级简单复制。

## 2. 系统功能

### 2.1 功能总览

```
IDE 用户行为 ──► 事件采集 ──► 日志/工件/图谱 ──► 七项上下文 ──► 面板 / JSON 导出
                     │              │                 │
                     │              ├── Task 识别      │
                     │              └── 软关系观察      │
                     └── 一律经 L2 Ingress
```

### 2.2 功能列表

| 编号 | 功能 | 说明 |
|------|------|------|
| F1 | 行为采集 | 编辑、选区/光标、活动编辑器切换、重命名、终端命令（start/end 能力依编辑器 API） |
| F2 | 日志结构化 | Raw 事件 → `LogItem` / `Artifact`，写入 `LogStore`，可持久化 |
| F3 | RepoMap | 代码片段、符号级工件上下文（引用/调用/实现等）、ripgrep 搜索、缓存 |
| F4 | 软关系 | 观察光标停留与回环跳转，维护软关系图并周期落盘 |
| F5 | 七项上下文 | 见 §2.3，随行为增量更新 |
| F6 | 任务识别 | 周期对日志做聚类/剪枝，经 LLMPort 归纳 Task，写入 `TaskStore` |
| F7 | 去重与导出 | `deduplicate` + `toJSONObject` / `toAbstract` / `checkCompleteness` |
| F8 | 实时面板 | 侧边栏 WebView，约 500ms 拉取 snapshot |
| F9 | 命令 | 导出 JSON 到数据目录、复制到剪贴板、打开面板/设置 |
| F10 | 可配置持久化 | `foreshadow.saveDir` 等 |

### 2.3 七项动态上下文

| 字段 | 含义 | 主要触发 |
|------|------|----------|
| **CursorContext** | 当前光标位置与上下窗口代码（含光标标记） | 光标/选区变化 → `updateByCursor` |
| **AttentionZone** | 近期关注过的代码片段集合 | 光标更新时追加并裁剪 |
| **SoftRelContext** | 与当前光标/最近工件相关的软关系片段 | 日志更新时查询软关系图 |
| **KeywordContext** | 从光标/历史抽取关键词，经 grep 得到的片段 | 光标更新，带节流（默认 3s） |
| **LastArtifactContext** | 最近编辑/选中工件的结构化上下文（引用等） | History 中最近带 location 的 Edit/Select |
| **History** | 近期关键行为摘要（最多 5 条，经 merge） | `updateByLog`；类型见下 |
| **Task** | 当前任务名与描述 | TaskRecognizer → `updateByTask` |

**History 允许的事件类型：**

- `EditTextDocument`
- `SelectText`
- `ExecuteTerminalCommand`

处理管线：`mergeEditLogs` → 按类型过滤 → `slice(-5)`。终端事件**进入 History**，但**不参与** `lastArtifact` 选取。

### 2.4 导出 API

`Foreshadow`（L3）对外：

| 方法 | 作用 |
|------|------|
| `toJSONObject()` | 结构化 JSON（导出前 `deduplicate`） |
| `toAbstract()` | 面向提示词的文本摘要 |
| `checkCompleteness()` | 0–1 完整度启发式 |
| `clone()` | 浅拷贝状态（共享 query 服务） |

`FoundationRuntime` 封装：

- `getSnapshot()`：context + completeness + 最近 logs/tasks + abstract（供 WebView）
- `exportContextJson()`：美化后的 `toJSONObject` 字符串

### 2.5 非目标（明确不做）

- CursorPredictor 推理（LLM/规则预测落点）
- CPInterface / Tab 采纳 UI
- Distiller / CPPair / `cursor_listener.py`
- line-comp-check
- 用户画像 / 知识点 / Q-Matrix
- 运行时依赖 VirtualME

## 3. 架构设计

### 3.1 设计原则

1. **严格分层**：平台 API 与领域逻辑隔离；L2/L3 零 `vscode` 依赖（eslint 强制）。
2. **Port 与适配器**：I/O、LSP、搜索、配置、调度、LLM 均由 L2 声明接口、L1 实现。
3. **单一事件入口**：所有 Host 事件进入 L2 `EventIngress`，禁止 L1 直调 L3 更新方法。
4. **领域类型通货**：`FsUri` / `Position` / `Range` / `Location` / `SymbolRef` 替代 vscode 类型。
5. **可替换 Host**：换编辑器时只换 L0/L1，保留 foundation + context。

### 3.2 四层结构

```
┌─────────────────────────────────────────────────────────────┐
│  L0  Extension Shell                                        │
│  src/extension.ts — activate/deactivate、DI 组装、生命周期     │
└────────────────────────────┬────────────────────────────────┘
                             │ 构造 Ports / Runtime / Bridge
┌────────────────────────────▼────────────────────────────────┐
│  L1  Host Adapter（唯一允许 import 'vscode'）                 │
│  src/host/vscode/                                           │
│  · EventBridge：VSCode 事件 → RawHostEvent                  │
│  · ports/*：Port 的 VSCode/Node/LangChain 实现               │
│  · mapper：vscode ↔ 领域类型                                 │
│  · commands / webview：命令与面板                            │
└────────────────────────────┬────────────────────────────────┘
                             │ publish / Port 调用
┌────────────────────────────▼────────────────────────────────┐
│  L2  Data Foundation（禁止 vscode）                          │
│  src/foundation/                                            │
│  · EventIngress、LogStore/TaskStore、RepoMap、kw、task       │
│  · domain + ports 声明 + runtime 编排                        │
└────────────────────────────┬────────────────────────────────┘
                             │ updateBy* / ContextQueryService
┌────────────────────────────▼────────────────────────────────┐
│  L3  Context（禁止 vscode）                                   │
│  src/context/foreshadow.ts — 七项上下文、去重、导出           │
└─────────────────────────────────────────────────────────────┘
```

**依赖方向（只允许自上而下）：**

```
L0 → L1 → L2 → L3
```

- L1 **实现** L2 的 Ports，**不** import L3 业务类去直接改上下文。
- L2 **可以**持有 L3 `Foreshadow` 实例（由 `FoundationRuntime` 组装），向其转发更新。
- L3 **仅**依赖 `ContextQueryService` 抽象（运行时注入 `RepoMap`）。

### 3.3 依赖与禁止项

| 规则 | 说明 |
|------|------|
| L2/L3 禁止 `import 'vscode'` | `eslint.config.mjs` → `no-restricted-imports` |
| L1 禁止直接 `Foreshadow.update*` | 必须 `runtime.publish(RawHostEvent)` |
| LangChain 仅 L1 | `LangChainLLMPort`；L2 只用 `LLMPort` |
| L3 不直接使用底层 Port | 统一 `ContextQueryService` |

### 3.4 数据流（端到端）

```
IDE 用户动作
    │
    ▼
L1 EventBridge  ──RawHostEvent──►  FoundationRuntime.publish
                                          │
                                          ▼
                                   L2 EventIngress
                    ┌─────────────────┼─────────────────┐
                    ▼                 ▼                 ▼
             Log 结构化        SoftRel 观察        cursor 路由
                    │                 │                 │
                    ▼                 ▼                 ▼
               LogStore          SoftRelMap        Foreshadow
                    │                                 ▲
                    │  onChange → updateByLog          │
                    │                                 │
               TaskRecognizer ──► TaskStore ──► updateByTask
                    │
                    │  (LLMPort / DocumentPort)
                    ▼
               RepoMap (ContextQueryService)
                    ▲
                    │  L3 查询片段 / 工件 / 软关系 / grep
                    │
               toJSONObject() / getSnapshot()
                    │
          ┌─────────┴─────────┐
          ▼                   ▼
   WebView 面板          export / copy 命令
```

### 3.5 事件模型

#### 3.5.1 RawHostEvent（L1 → L2）

定义于 `foundation/domain/raw-events.ts`：

| type | 主要字段 | 来源（VS Code） |
|------|----------|-----------------|
| `textChanged` | uri, beforeText, afterText, changes | `onDidChangeTextDocument` |
| `selectionChanged` | uri, selections, active, kind | `onDidChangeTextEditorSelection` |
| `activeEditorChanged` | uri, lineCount… | `onDidChangeActiveTextEditor` |
| `fileRenamed` | oldUri, newUri | `onDidRenameFiles` |
| `terminalCommand` | processId, cmd, output, phase | Shell execution start/end API |

#### 3.5.2 EventIngress 处理摘要

| 事件 | 行为 |
|------|------|
| `textChanged` | 跳过忽略文件 → 结构化 Edit 日志 → `LogStore.add` → `updateByLog` |
| `selectionChanged` | `observeCursorMove` → `updateByCursor`；真实选区则 Select 日志 → `updateByLog` |
| `activeEditorChanged` | 切换文档日志 → `updateByLog` |
| `fileRenamed` | 重命名日志 → `updateByLog` |
| `terminalCommand` | `phase === 'end'` 时终端日志 → `updateByLog` |

#### 3.5.3 监听范围（相对 VirtualME 裁剪）

**保留：** 编辑、选中、活动编辑器、重命名、光标 active、终端执行。  
**去掉：** lint、终端 open/close、hover、Python CursorJump、蒸馏相关。

### 3.6 Host Ports

L2 声明（`src/foundation/ports/`），L1 实现（`src/host/vscode/ports/`）：

| Port | 职责 | 典型 L1 实现 |
|------|------|----------------|
| `DocumentPort` | 打开/读取文档快照、行文本 | `VscodeDocumentPort` |
| `LanguageIntelPort` | symbols / definition / refs / impl / call hierarchy / hover 等 | `VscodeLanguageIntelPort` |
| `WorkspaceSearchPort` | 工作区文本搜索（ripgrep） | `VscodeWorkspaceSearchPort` |
| `WorkspacePort` | roots、路径、extensionPath、dataDir | `VscodeWorkspacePort` |
| `FileSystemPort` | 读写、mkdir | `NodeFileSystemPort` |
| `ConfigPort` | 配置读写与变更 | `VscodeConfigPort` |
| `SchedulerPort` | interval / timeout | `NodeSchedulerPort` |
| `LLMPort` | chat + tools | `LangChainLLMPort` |

L3 侧门面：

| 接口 | 实现 | 用途 |
|------|------|------|
| `ContextQueryService` | `RepoMap` | 代码片段、工件上下文、软关系、grep、按 range 取 Artifact |

### 3.7 领域模型（节选）

```ts
// geometry
interface FsUri { fsPath: string; scheme?: string }
interface Position { line: number; character: number } // 0-based
interface Range { start: Position; end: Position }
interface Location { uri: FsUri; range: Range }

// 行为与任务
LogItem { eventType, artifact?, ... }
Task { name, description, logs }
Artifact { name, kind, location?, ... }
```

`EventType` 枚举包含 Open/Close/Edit/Select/Rename/ExecuteTerminalCommand 等；当前采集路径主要产出 Edit、Select、ChangeTextDocument、Rename、ExecuteTerminalCommand 等子集。

### 3.8 去重策略

导出前 `deduplicate()`：

1. 各字段内部去重 / trim；
2. 全局优先级（高优先保留，低优先融合后删除重复项）：

```
CursorContext
  > AttentionZone
  > SoftRelContext
  > KeywordContext
  > LastArtifactContext
```

相等判定与融合由 `ArtifactContextItem.epualsTo` / `fusion` 等完成。

### 4.2 L0：`src/extension.ts`

**职责：** 插件激活与销毁；组装全部 L1 Port → `FoundationRuntime` → `EventBridge` → `ForeshadowPanelProvider` → `registerCommands`。

**关键顺序：**

1. 创建 Ports（config / workspace / documents / languageIntel / search / fs / scheduler / llm）
2. `new FoundationRuntime(ports)` → `runtime.start()`（启动 TaskRecognizer 定时器）
3. `new EventBridge(runtime)` → `start()` 订阅 VS Code 事件
4. 注册 WebView Provider 与命令
5. dispose 时先 bridge 再 runtime

L0 **不包含**业务算法，只做组合根（Composition Root）。

### 4.3 L1：`src/host/vscode/**`

#### 4.3.1 `event-bridge.ts`

- 维护 `beforeTextMap`，为 `textChanged` 提供编辑前文本；
- 将 vscode 事件映射为 `RawHostEvent` 后 `runtime.publish`；
- 终端：兼容 `onDidStartTerminalShellExecution` / `onDidEndTerminalShellExecution`，汇总输出与成功/失败标签。

#### 4.3.2 `mapper.ts`

- `vscode.Uri` / `Position` / `Range` / `Location` ↔ 领域类型；
- 保证 L2 只见 `FsUri` 等。

#### 4.3.3 `ports/*`

| 文件 | 实现要点 |
|------|----------|
| `document-port.ts` | 基于 `vscode.workspace` 打开/读文档，产出 `TextDocumentSnapshot` |
| `language-intel-port.ts` | 封装 `vscode.execute*Provider` 类命令 |
| `workspace-port.ts` | workspaceFolders、路径、`extensionPath`、dataDir 解析 |
| `workspace-search-port.ts` | 调用内置/脚本目录 ripgrep |
| `filesystem-port.ts` | Node `fs` 读写 |
| `config-port.ts` | `workspace.getConfiguration('foreshadow')` |
| `scheduler-port.ts` | `setInterval` / `setTimeout` 封装 dispose |
| `llm-port.ts` | LangChain OpenAI 兼容客户端，读 ConfigPort |

#### 4.3.4 `commands.ts`

注册四条命令；导出时用 `FileSystemPort` 写文件，配置读 `saveDir`。

#### 4.3.5 `webview/panel-provider.ts`

实现 `WebviewViewProvider`；读取 `media/panel.html`；按 `UIUpdateInterval` 推送 snapshot。

### 4.4 L2：`src/foundation/**`

#### 4.4.1 `runtime.ts` — FoundationRuntime

编排中枢：

| 成员 | 角色 |
|------|------|
| `logStore` / `taskStore` | 日志与任务存储 |
| `repoMap` | 实现 `ContextQueryService`，并 `setArtifactContextQueryService` |
| `foreshadow` | L3 实例 |
| `ingress` | 事件入口 |
| `taskRecognizer` | 周期任务识别 |
| `publish` | 转发给 ingress |
| `getSnapshot` / `exportContextJson` | 对外只读视图 |

订阅：`logStore.onChange` → `foreshadow.updateByLog`；`taskStore.onChange` → `updateByTask`（与 recognizer 回调双通道保持一致）。

#### 4.4.2 `ingress/event-ingress.ts`

唯一业务侧事件入口；将 Raw 事件转为日志/观察/光标更新（见 §3.5.2）。对 `Foreshadow` 仅依赖 `ForeshadowUpdater` 窄接口（`updateByLog` / `updateByCursor`）。

#### 4.4.3 `domain/`

| 模块 | 内容 |
|------|------|
| `geometry.ts` | FsUri、Position、Range、Location 及 factory |
| `raw-events.ts` | RawHostEvent 联合类型 |
| `event-types.ts` | EventType 枚举 |
| `log-item.ts` | 行为日志模型与序列化 |
| `artifact.ts` / `artifact-context.ts` | 工件与上下文条目、去重/裁剪 |
| `task.ts` | 任务模型 |

#### 4.4.4 `ports/`

接口声明集中导出（`ports/index.ts`）。**无实现、无 vscode**。`context-query.ts` 为 L3 查询门面。
